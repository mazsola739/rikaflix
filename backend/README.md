# Rika Netflix – backend

REST API for the movies and TV shows of Rika Netflix, built with **Express**, **TypeScript** and **Zod**.
Data lives in a single JSON file ([`data/shows.json`](data/shows.json)), so no database is needed.

## Scripts

| Command          | What it does                                                    |
| ---------------- | --------------------------------------------------------------- |
| `yarn dev`       | Starts the API on <http://localhost:5000> and restarts on change |
| `yarn start`     | Runs the API without file watching (TypeScript runs via `tsx`)  |
| `yarn build`     | Same as `typecheck`: there is no compile step, `tsx` runs the sources |
| `yarn typecheck` | Type-checks sources and tests                                   |
| `yarn test`      | Runs the API tests (Vitest + Supertest)                         |

## Configuration

All settings are optional environment variables:

| Variable          | Default                 | Meaning                                    |
| ----------------- | ----------------------- | ------------------------------------------ |
| `PORT`            | `5000`                  | Port the API listens on                    |
| `SHOWS_DATA_FILE` | `data/shows.json`       | JSON file used as the database             |
| `CORS_ORIGIN`     | `http://localhost:3000` | Origin allowed to call the API from a browser |

In development the frontend calls the API through the Vite proxy, so CORS only matters if you call the API from somewhere else.

## Data model

```ts
interface Show {
  id: string               // UUID, generated by the server
  type: 'Movie' | 'TV show'
  title: string
  tagline: string
  vote_average: number     // 0–10
  release_date: string     // YYYY.MM.DD
  poster_path: string      // 'images/posters/…' (shipped with the frontend) or an http(s) URL
  backdrop_path: string    // 'images/backdrops/…', an http(s) URL, or ''
  overview: string
  genres: string[]         // e.g. ['Action', 'Sci-fi']; first letter is capitalised on save
  runtime: number          // minutes
}
```

The bundled data set holds **614 shows** (434 movies, 180 TV shows).

## API

Base URL: `http://localhost:5000/api`. Every response is JSON.

### `GET /shows`

Lists shows with filtering, sorting and pagination. All query parameters are optional:

| Parameter | Values                                                                    | Default             |
| --------- | ------------------------------------------------------------------------- | ------------------- |
| `type`    | `All`, `Movie`, `TV show`                                                 | `All`               |
| `title`   | text, matched case-insensitively anywhere in the title                    | –                   |
| `genres`  | comma-separated list, e.g. `Action,Drama` (`All` = no genre filter)       | `All`               |
| `sortBy`  | `Release date asc/desc`, `Rating asc/desc`, `Title asc/desc`              | `Release date desc` |
| `limit`   | 1–100                                                                     | `15`                |
| `page`    | 1…                                                                        | `1`                 |

The filters are combined: a show must match the type, the title **and** at least one of the genres.

```http
GET /api/shows?type=TV%20show&genres=Comedy&sortBy=Rating%20desc&limit=3
```

```json
{
  "allShowOfType": [ /* every show of the requested type */ ],
  "filteredShows": [ /* every show matching all filters (unsorted) */ ],
  "showsOnPage":   [ /* the sorted shows of the requested page */ ],
  "foundShows": 40
}
```

The frontend uses `allShowOfType` for the animated poster header and the random pick, and `filteredShows` to build the genre tabs.

### `GET /shows/:id`

Returns one show, or `404 { "message": "Show not found" }`.

### `POST /shows`

Creates a show. The body is a `Show` without `id` (any `id` sent is ignored). `backdrop_path` and `overview` are optional.
Answers `201` with the created show, including its new `id`.

### `PUT /shows/:id`

Updates any subset of the fields; the `id` never changes. Answers `200` with the updated show, or `404`.

### `DELETE /shows/:id`

Deletes a show. Answers `200 { "id": "…" }`, or `404`.

### `GET /health`

Answers `{ "status": "ok" }`.

### Errors

Invalid input answers `400` with every problem found:

```json
{
  "message": "Validation failed",
  "errors": [{ "field": "release_date", "message": "Release date must be in YYYY.MM.DD format" }]
}
```

Unknown routes answer `404 { "message": "Not found" }`, malformed JSON `400`, unexpected failures `500`.

## Project structure

```
backend/
├── data/shows.json          the "database"
├── src/
│   ├── server.ts            entry point: loads data, starts listening
│   ├── app.ts               builds the Express app (used by server and tests)
│   ├── config.ts            environment-based settings
│   ├── routes/              URL → middleware + controller wiring
│   ├── validators/          Zod schemas and the validate() middleware
│   ├── controllers/         HTTP handlers (status codes, responses)
│   ├── repositories/        reads/writes the JSON file (atomic writes)
│   └── middlewares/         404 and error handlers
└── tests/shows.test.ts      API tests on a temporary copy of the data

../shared/                   used by the backend AND the frontend's browser mode
├── show.ts                  the Show model, sort options, query/response types
└── showQuery.ts             queryShows(): filtering, sorting, paging
```

Images are not served by the backend: they live in `frontend/public/images` and are served with the frontend
(by Vite in development, by GitHub Pages in production). The data only stores their relative path.

## Not implemented yet

- Authentication: anyone who can reach the API can add, edit or delete shows.
- Concurrent writers: the JSON file suits a single server process, not a cluster.
